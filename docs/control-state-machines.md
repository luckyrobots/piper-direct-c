# PiPER control state machines

This inventory covers the PiPER plugin, managed controller and gripper services, native controller, and web clients. It includes transitions encoded in flags, request lifetimes, telemetry comparisons, and timers as well as explicit enums. The physical firmware and Lucky Engine runtime appear here at their observable protocol boundaries.

**P0** marks motion authority, power, and stopping. **P1** marks evidence and presentation used by those decisions. **P2** marks workflows that can evolve separately. Each row names the owner and its transition evidence. Keep a transport acknowledgement, a measured outcome, and a UI label distinct.

## Lucky Engine plugin

**Explicit** means a named state or transition owner enforces the progression. **Implicit** means state is encoded in flags, evidence, tasks, or timers. **Mixed** combines the two. The tables describe production paths. Historical report formats and test fixtures are listed only where they affect the live path.

### Concurrency transitions checked in regression fixtures

| Owner | From and event | Required next state or effect |
| --- | --- | --- |
| UI actor | A movement click is queued as Follow installs, or arrives while Follow owns the selected controls. | The captured ownership epoch or ingress guard rejects it. Retirement cannot make the same event eligible. |
| Follow coordinator | A native or engine ACK arrives after Cancel or STOP. | Finish accounting for already-admitted work. Continue retirement and independent cleanup. No phase advance. |
| Ordered source | Activation is acknowledged but the primer drains slowly, or the source expires after phase computation. | Preserve the activation timestamp. Reject ordered sends after expiry and retire the session. |
| Recovery operation | STOP revokes the epoch while reset or an Enable continuation is outstanding. | No fresh grant, final approval or target from the old operation. |
| Recovery operation | Operator cancels while a zero request is active. | Permit cleanup to inspect the same owned request and send a scoped STOP. Retire its heartbeat even if STOP cannot be verified. |
| View publication | Navigation fails validation or is cancelled while waiting for publication. | Retain the previously committed context and valid widget IDs. |
| Camera picker | Discovery reorders options or replaces the scene while an old menu is displayed. | Resolve the exact ID the view showed. Reject a removed ID or a replaced scene. |
| Calibration placement | The primary empty-prefix arm shares a root or a sibling mapping appears before apply. | Reject the scene write after live model validation. |
| Calibration markers | A manual selection arrives while a background batch waits for an editor acknowledgement. | Join the old batch, then commit the selection and publish the new batch. |
| Pika shutdown | One device stalls or returns unusable disable evidence while another is already verified. | Continue the verified peer's independent cleanup. Disconnect only after exact-device evidence. |
| Host Pika routing | Discovery pauses after an idle arm check. Arm motion starts before discovery returns. | Recheck under the native command gate at routing commit. Discovery and peer operations do not hold that gate. |
| Host state frame | Sampling the arm and grippers takes measurable time. | Stamp before sampling, and derive the default Pika projection and inventory from one sample per session. |
